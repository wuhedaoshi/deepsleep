# 产物目录

| 文件 | 说明 |
|---|---|
| `Deepsleep-1.3.8.apk` | **当前版本（实验线，1.2.8 线）**：自动 + 手动上下文压缩（DSH 机制：800k 触发、155k 逐字保留、结构化 checkpoint、溢出重试一次、`/compact` 与按钮手动触发）。versionCode 83 |
| `Deepsleep-1.3.7.apk` | 1.3.6 基线（模型/思考强度/价格峰谷）+ 导入导出重做（流式导出、按会话渐进导入、孤儿清理、两个真 bug）。versionCode 79 |
| `Deepsleep-1.2.8.apk` | 稳定线：官方 v3 导出 + 原生 SAF 落盘。versionCode 70 |
| `Deepsleep-1.2.7.apk` | 改名 + 换图标那一版 |
| `Deepseek-API版-1.2.6.apk` | 大包导入重做（应用名还是旧的） |

`history/` 放改名或里程碑之前的版本。

只保留能装、能验证的版本。1.3.8–1.4.4（修贪婪 id 正则、`nullable` 缺键、清库 70 秒那几轮）与 1.3.9（联调用 mock 构建，接口指向 `127.0.0.1:8099`）都已删除——**尤其别装 1.3.9，它连不上真实接口**。

**versionCode 不单调的历史**：两条旧线各走各的号（`Deepseek-API版` 到 1.2.5 是 32，`Deepsleep` 的 1.2.5/1.3.6 是 45~50）。1.2.6 把基数抬到 60 之后逐次 +1；联调期被 mock 构建占掉 80/81，1.3.8 最终是 82。`versionName` 与 `versionCode` 相互独立——Android 只按 versionCode 判升级，所以调试期把名字推高了也能在发版时定回来。

**两条线怎么并存**：只有一个 applicationId 和一条版本流，实验版是同一身份的另一个构建，直接覆盖安装、数据继承；回退时重新导入 ZIP。
