# 诊断日志设计

目标：**记状态与因果，不记内容。** 出了问题能一次定案，又不需要用户做任何选择。

这份文档是排障事故之后写的，每一条都对应一次真实的瞎飞。改日志前先读它。

## 一、字段白名单

结构化 JSONL，字段只有白名单里的，**没有自由文本字段**。

### 必须记

| 字段 | 含义 | 隐私 |
|---|---|---|
| `v` | 协议版本，方便以后解析 | — |
| `build` | 应用 versionName/versionCode | — |
| `os` / `wv` | Android 版本、WebView 内核版本号 | — |
| `sid` / `view` / `op` | 随机会话 ID / 页面实例 ID / 操作 ID（只用于把一次操作的记录串起来，**不可跨会话追踪**） | 随机值 |
| `seq` / `t` / `mono` | 序号 / 墙上时间 / 单调时钟（判耗时，防系统时间跳变） | — |
| `event` / `stage` / `code` / `ms` | 事件名 / 阶段 / 错误码 / 耗时 | — |

### 有用（按需开，默认开）

| 字段 | 含义 | 隐私处理 |
|---|---|---|
| `attachments` / `sizeBucket` | 附件**个数**与大小**区间**（如 `1-5MB`） | 不记文件名、不记精确字节 |
| `http` | 状态码 | — |
| `dom` / `hit` / `draw` / `pixel` | 渲染指标：文本长度区间、命中元素数、绘制次数、非白千分比 | 只记数字 |
| `stack` | 崩溃栈，**只保留自有代码的 文件:行**，第三方帧与参数全部丢弃 | 见「禁止」 |

### 禁止

正文、附件名与内容、URL、API Key（连哈希也不记）、请求/响应头与体、完整文件路径、
设备标识（IMEI/ANDROID_ID/序列号）、账号标识、剪贴板内容、输入法输入、DOM 文本、截图、
原始异常字符串（可能含用户数据）。

> 正则脱敏只作兜底，不能当作许可去记内容。参考 Android 官方对日志泄露的提示：
> https://developer.android.com/privacy-and-security/risks/log-info-disclosure

## 二、每次踩坑「本该记下」的那一行

| 事故 | 一次定案的日志 |
|---|---|
| A 旧 WebView 缺 `Array.prototype.at` / `toReversed` → 白屏 | `{"event":"boot_fail","hasAt":false,"hasToReversed":false,"code":"JS_API_MISSING","site":"main.js:42"}` |
| B 「发你好 → 上传失败」分不清阶段 | `{"op":7,"attachments":0,"stage":"prepare","http":401,"code":"UPLOAD_FAILED"}` |
| C 「填完 Key 就白屏」DOM 正常 | `{"event":"blank","textBucket":"64-127","hit":9,"drawDelta":5,"capture":"ok","pixel":0,"nativeBar":true}` |
| D 自动恢复误判 → recreate 循环 | `{"event":"recovery","rule":"pixel_only","attempt":48,"action":"blocked"}` |
| E 导出 `.txt.zip` / 复制失效 | `{"event":"export","format":"text","suffix":".zip","code":"FORMAT_MISMATCH"}` |

要点：**每条都带 `code`**。没有错误码的日志等于散文。

## 三、存储与自保

- **异步有界队列**：日志写盘失败不重试、不递归；队列满时丢弃并**记一条 `dropped:N`**，别装作没发生
- **滚动按完整行**：按字节硬切会劈开 UTF-8，导出首行乱码（踩过）
- 私有目录 `files/logs/`，单文件 2 MB、保留一份 `.1`，上限约 4 MB；故障快照单独限 512 KB；7 天清理
- **不能只写 logcat**：用户导不出、设备上也没人看（踩过）
- 日志不得阻塞主线程：桥接调用只入队，落盘在原生线程

## 四、一次导出即含全部证据

导出接口必须合并：

1. 前端内存缓冲（当前 + 上次）
2. 原生日志文件（含 `[native]` / `[blank]` 前缀的事件）
3. 环境摘要：`build/os/wv/屏幕/DPR/语言/是否原生壳`
4. **故障快照**：崩溃或白屏发生时冻结的上下文（窗口尺寸、可见性、绘制次数、最近 20 条事件）
5. **缺口声明**：丢了多少条、哪些阶段没采到——诚实比完整重要

导出前先排空队列；超时就在文件里写明「此处有缺口」。

## 五、比加日志更有效的手段

日志是兜底，不是第一选择：

- **错误码贯穿各阶段**：`stage` + `code` 让「哪一步失败」不需要靠推断
- **故障自动冻结状态**：崩溃/异常时抓一次现场，比连续流水账有用得多
- **回归测试**：旧 WebView 兼容（删 API 模拟）、导出格式、复制链路——这三类 bug 用测试挡住比用日志发现便宜得多
- **自动回传**：需要单独、明确的用户同意，默认关闭；否则等于偷偷上传（隐私与合规风险）
