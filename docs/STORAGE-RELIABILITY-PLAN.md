# 存储可靠性与日志优化计划

## 核对结果

流式输出的逐帧更新写入内存，未发现逐帧写 IndexedDB。三条线已具备暂存表及事务提交，但大型归档导入绕过了暂存，提前清空正式库。保存错误有界面入口，后台自动重试与可导出的结构化诊断仍需补齐。

## 实施顺序

1. 公共底层。按会话分批暂存归档，最后单事务替换；导入或事务失败时保留旧库。保存遇到可恢复错误时退避重试，并用会话代次和当前保存任务阻止旧写入复活。记录存储、归档和启动诊断，只记错误类别与统计，不收集原始错误正文。
2. Android 自检。把最近提交的库计数和端口保存到原生存储。启动后对比实际会话数，疑似归零时保留最后已知记录，并给出进入数据管理的提示。
3. Android 自动备份。启动或成功保存后检查备份是否到期，24 小时内保留一次自动快照，非空历史才写入。原生私有目录保留最近三份已提交 ZIP。数据管理可按日期选取备份并确认恢复，正文和附件全部校验后再替换。
4. 实验线增强。压缩线记录压缩范围、耗时、保存状态；进阶线加路由和状态码诊断，先验证配置引用失效和回退不会把会话发给未预期的供应商。配置备份默认排除密钥。
5. 三条线使用同一个 v12 消息表结构。Android 已有历史时先写本地快照，写入失败则保留原库。迁移事务拆分消息和会话元数据，保留消息 ID、分支选择、压缩检查点和附件引用。浏览器走同一迁移事务，由用户通过手动导出保留外部备份。

## 验收

- 模拟暂存写入中断及提交事务失败，确认旧会话和附件仍可读取。
- 模拟临时数据库写入失败后恢复，以及删除和导入时旧重试不会复活数据。
- 原生水位线单独验证清空、切换端口与疑似存储归零。
- 分线运行类型检查与回归测试。签名、发布属于独立交付步骤。

## 本轮交付状态

- 三条线均已实现保存退避、生命周期失效保护、存储诊断、原子导入和原生水位线提示。归档若没有任何会话成功暂存，会终止导入。
- 两条实验线已记录摘要前后轮次数、节省估算和耗时。进阶线已记录聊天协议、路由类型和思考档位。
- 三条线通过存储故障注入回归，包括暂存中断、事务回滚、两个临时写入错误后的恢复，以及删除拦截旧重试。水位线的判断逻辑已在模拟桥上验证。
- 三条线已接入轮转与恢复。原生自动快照使用本地格式，保留消息 ID、压缩与分支状态。手动历史导出继续使用官方兼容 ZIP。应用私有备份会随清除应用数据或卸载一起删除。
- 进阶线支持独立导入和导出供应商配置，也在历史 ZIP 中保存配置快照。密钥留在本机。导入优先保留现有资料，自定义服务分配在补齐凭据后由用户确认。
- 三条线通过类型检查、静态检查、前端构建、Android 原生编译，以及迁移失败、回滚、坏附件和精确还原测试。Java 本机测试覆盖三份轮转和中断保护。Android 真机强杀、空间不足和超大归档仍需验收。

会话列表为空时，启动会先检查正文库。正文仍在则事务性重建摘要索引；两者均为空则记录诊断。界面区分「重试保存」「重新读取」与「打开数据管理」。三条线的新构建均会升到 v12。旧构建无法直接打开 v12 数据库，回退时先从新版导出通用 ZIP，再用旧版导入。暂存恢复期间会同时占用当前库和待导入数据的空间。
